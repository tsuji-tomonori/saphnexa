## 背景

`plan-20260529.txt` は API schema / model catalog / tool contract / DB type を共有する必要があるとしている。現在の `packages/db-schema` は required table 名の TS source を持つが、主要 table の列、主キー、JSON/timestamp/UUID 境界は SQL migration 側にしかない。

## 目的

Aurora DSQL/Flyway migration と同期する主要 DB table metadata を TypeScript source として追加し、API / Agent / Web が参照できる DB type surface を一段進める。

## スコープ

- `packages/db-schema/src/table-metadata.ts` に主要 table の列、主キー、列種別 metadata を追加する。
- `packages/db-schema` と root typecheck に metadata source を含める。
- source gate で TS metadata と `V001__initial_saphnexa_schema.sql` の主要 table/column token 同期を確認する。
- local verification docs に DB table metadata source gate を追記する。
- 実 DB introspection/codegen、Aurora DSQL 接続、Flyway 実適用は扱わない。

## 実装計画

1. Chat / RAG / realtime / admin artifacts / audit / tool invocation に関係する主要 table metadata を TS source として追加する。
2. `tools/check-type-surface.js` へ table metadata と migration の同期検査を追加する。
3. docs と task に検証結果を記録する。
4. typecheck、DB migration check、契約テスト、docs check、diff check を実行する。

## ドキュメント保守方針

実運用手順は変えないため、`docs/ops/local-verification.md` の local/source gate 説明だけを最小更新する。

## 受け入れ条件

- [x] `packages/db-schema/src/table-metadata.ts` が主要 DB table metadata を typed source として export する。

## リスク・制約

- 今回の metadata は migration source 由来の static type surface であり、実 DSQL introspection 生成物ではない。
- 全 38 table の全列網羅ではなく、API/Agent/Web/RAG/realtime に関わる主要 table の typed metadata から進める。
